# Pause Resume Audio Fade for Windows

動画や音楽の**一時停止・再開・シーク**のたびに、音を自動でフェードさせる常駐アプリです。
ブラウザ拡張版・Mac版のWindows移植で、アプリごとの設定は不要。PCから鳴る音全体に効きます。

- **一時停止**: ブツッと切れず、自然にフェードアウトして消える
- **再開**: ふわっとフェードインで戻る(既定300ms)
- **シーク**: シーク直後だけフェードイン

## かんたん導入(初心者向け)

1. [Releases](../../releases) から `PauseResumeAudioFade.exe` をダウンロードします(.NET などの追加インストールは不要)。
2. ダブルクリックで起動します。
   - 「WindowsによってPCが保護されました」と出たら、**「詳細情報」→「実行」**を押してください(個人開発で署名していないための表示です)。
3. 初回だけ案内画面が出ます。
   - **「✔ 準備できました」** と出たら、もう使えます。動画を再生して一時停止・再開してみてください。
   - **「もう1つだけ準備が必要です」** と出たら、画面の手順どおりに [VB-CABLE](https://vb-audio.com/Cable/)(無料の仮想ケーブル)を入れてください。入れ終わると自動で動き始めます。
4. 画面右下(タスクトレイ)に常駐します。アイコンの右クリックで、設定の変更・「Windows起動時に自動起動」・終了ができます。

### 何が必要になるのか

フェードアウトをかけるには、元の音を鳴らさずに逃がす「使っていない出力」が1つ必要です(理由は下の「仕組み」)。

| あなたのPC | 必要なもの |
|---|---|
| 仮想ケーブル(VB-CABLE)が入っている | そのまま使えます |
| スピーカーとヘッドホン、PCモニター(HDMI/DP)など、**出力が2つ以上ある** | **何も入れなくて使えます**(使っていない方を、一時的にミュートして借ります。終了すると元に戻ります) |
| 出力が1つだけ(ノートPCのスピーカーだけ、USBヘッドセットだけ等) | VB-CABLE を入れてください(案内画面が手順を出します) |

> **VB-CABLE について**: VB-Audio Software の寄付制(donationware)ソフトで、個人利用は無料です。
> インストールには管理者権限が必要で、再起動を求められることがあります。入れるかどうかは、このアプリが勝手に行うことはありません。

## 設定(トレイメニュー)

| 項目 | 内容 |
|---|---|
| 有効 | オン/オフ(アイコンのダブルクリックでも切替) |
| フェードアウトを使う | オフにするとフェードインのみ |
| プリセット | 下表。**既定は「音楽」**(Mac版の音楽向けと同じ) |
| フェードイン長 | 150 / 300 / 500 / 1000 / 2000 ms |
| 出力デバイス | 実際に鳴らすデバイス(既定は「いつも聞いているデバイス」) |\r\n| 新しく接続したヘッドホン等へ自動で切り替える | 既定はオン |
| はじめに / 導入ガイド | 案内画面をもう一度開く |

| プリセット | 先読み(音が遅れる量) | フェードアウト長 |
|---|---|---|
| 短い | 50ms | 34ms |
| 標準 | 100ms | 84ms |
| 長い | 200ms | 184ms |
| **音楽(既定)** | 350ms | 334ms |

先読みを長くするほど自然に消えますが、映像との音ズレが大きくなります。**動画で音ズレが気になるときは「標準」に**してください。

検出の目安(Mac版に準拠): 無音が **250ms以上** → 一時停止→再開 / **60〜250ms** → シーク / それより短い無音は瞬断として短いフェードインのみ。

設定とログ: `%APPDATA%\PauseResumeAudioFade\`(`settings.json`、`log.txt`)

## 仕組み

Windowsには、他アプリの音を「止まる前に」加工する公式の入り口がありません。ブラウザは一時停止した瞬間に
サンプルを出さなくなるので、「止まったと分かった時点」では、もうフェードさせる音が残っていません。
そこで、音を少し遅らせてから鳴らし、止まったと分かった時点で**遡ってフェードアウト**をかけます。

```
アプリ(ブラウザ等) → [使っていない出力(既定の再生デバイスに切替)] → ループバック取り込み
   → 先読みで遅延 + 一時停止を検出して遡ってフェードアウト → 実際のスピーカー/ヘッドホン
```

- 元の音は「使っていない出力」へ流れて鳴らないので、**遅延させて加工した音だけ**が聞こえます。
- Windowsの音量スライダーや音量キーは、実際の出力デバイスの音量に連動します。
- イヤホンの抜き差し、デバイスの無効化、スリープ復帰があっても、数秒以内に自動で立て直します。\r\n- ヘッドホンやUSB DACなどを**新しく接続すると、自動でそちらから鳴ります**(トレイメニューでオフにできます)。モニター出力(HDMI/DP)・スピーカー・Bluetoothの通話用(ハンズフリー)・仮想ケーブルへは自動では切り替えません。
- アプリが異常終了しても、見張りプロセスが既定の再生デバイスとミュートを元に戻します。

VB-CABLEなしでできないか、他の方法(プロセス別ループバックでのミュート、極小音量+補正、自前ドライバ、システムAPO)を調べて実測した結果は
[docs/research-without-vb-cable.md](docs/research-without-vb-cable.md) にあります。

## 既知の制限

- 複数のアプリが同時に鳴っているとき、**ミックス全体が無音になったときだけ**フェードします(一方だけ止めても、もう一方が鳴っていれば効きません)。Mac版と同じ考え方です。
- 約20ms未満の瞬断は検出できません。
- 「余った出力を借りる」場合、そのデバイスを**明示的に指定して鳴らしているアプリ**の音は、動作中は消えます(使用中のデバイスは自動で避けます)。
- 借りた出力のOSDのミュート表示が出ることがあります。
- Windowsの「空間オーディオ(立体音響)」をオンにしていると、機器によって反響のような音が出ることがあります。オフにしてください。
- 音は約0.1〜0.35秒遅れます(プリセットによる)。
- 署名していないexeなので、SmartScreen やウイルス対策ソフトが警告することがあります。

## 開発

```
dotnet test tests/PauseResumeAudioFade.Tests                      # DSP・選択ロジックの単体テスト
dotnet publish src/PauseResumeAudioFade -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=none `
  -o dist/PauseResumeAudioFade                                    # 単一exe(約49MB、.NET不要)
```

| オプション | 用途 |
|---|---|
| `--console` / `--no-tray` | ログをコンソールにも出す / トレイ無しで動かす |
| `--sink <名前> --real <名前>` | 任意のデバイスを「使っていない出力」/「鳴らす先」に指定(自動選択を無効化) |
| `--mute-sink` | シンクをミュート(物理出力をシンクにするとき) |
| `--dump <dir>` | 取り込み前/後の生floatを記録(`poc/DumpAnalyzer` で解析) |
| `--restore` / `--quit` | 既定デバイス/ミュートを元に戻す / 起動中のアプリを正常終了 |

環境変数 `PRAF_CHAOS=1` と、設定フォルダの `chaos-hide.txt`(デバイスIDの断片)で、デバイスの抜き差しを疑似的に再現できます(自己修復の試験用)。

自動検証: `tests/e2e/run-e2e.ps1`(合成トーンで一時停止/シークを再現し、エンジンの出力を録音して波形の段差=クリックの有無を計測。`-Auto` で引数なしの自動選択経路を検証)。

構成:

- `src/PauseResumeAudioFade.Core` — 先読み+フェード処理(`LookaheadProcessor`)、デバイス選択(`SinkPlanner`)、パラメータ、PCM変換
- `src/PauseResumeAudioFade` — トレイアプリ、案内画面、ルーティングと自己修復(`RoutingEngine`)、既定デバイス切替(IPolicyConfig)、見張り
- `tests/` — 単体テストとE2E
- `poc/` — 検証用の試作と診断ツール(`AudioTool` など)
- `docs/` — 調査メモ
